Downloads and copies, from start to cancel.

Downloads and file copies keep running while their requested work is active. Finally displays progress and offers cancellation, then stops the foreground service when its queue finishes.

Text description of the demonstration
  1. The library tools offer Download to headset for the selected synthetic network video.
  2. The requested download shows progress and a cancel control, followed by its cancelled state.
  3. The file tools offer Copy to… for a synthetic local file. A destination is selected and Copy here starts the operation.
  4. The file copy shows progress and a cancel control, followed by its cancelled state.

1. Start and cancel a network download

  1. Select a source video and open MORE → Download to headset.
  2. Follow the transfer's status, percentage and copied bytes. Cancel download stops a queued or active copy.
  3. The cancelled transfer stays visible in its cancelled state. The source remains in place.

2. Start and cancel a local file copy

  1. Open MORE → Manage files → Copy to… for the selected item.
  2. Choose a writable destination and press Copy here. Choosing a folder alone does not start a copy.
  3. Follow progress and cancel the operation. The cancelled state remains visible; existing files are not overwritten.

A finalization step completes safely before the result is published. Cancellation is unavailable during that final step.

Foreground-service lifetime

The download and file-operation services use Android's dataSync foreground-service type for an explicit user-started queue. They provide a progress notification. Each service stops when no queued or active work remains; cancelling one item does not cancel other requested items.

Neither transfer service starts at boot or automatically resumes unfinished work after a process restart. Interrupted work requires another user action. These services do not keep running to browse a library or watch a movie.
